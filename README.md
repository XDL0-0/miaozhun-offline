# 瞄准专家本机离线版

Windows / Linux 本机离线训练包。Windows 可双击 `瞄准专家-离线版.exe`；Linux 可用系统 Node.js 启动。服务仅监听 `127.0.0.1:18746`，训练界面为 [http://127.0.0.1:18746/aim](http://127.0.0.1:18746/aim)。

`site/` 保存采集的原始公开客户端资源，`dist/` 保存可运行的离线版本。`prepare-offline.mjs` 根据原始资源及版本化补丁重建 `dist/`；`verify-offline.mjs` 检查素材、场景和 JavaScript。Windows 自带 Node 运行时位于 `runtime/`。

成绩、设置、收藏、录像与编辑器草稿保存在使用此应用的浏览器本机存储中，不包含在仓库内；可在界面中点击“完整备份”单独导出。

## 界面语言

左下角“界面语言 / Language”可切换简体中文和 English，默认中文，选择保存在本机。切换时重新载入界面；编辑器会先保存并核对当前草稿，保存失败时保留当前页面。

英文覆盖训练目录、设置、准星、键位、枪械皮肤、训练 HUD、暂停、结算、回放与场景编辑器。枪械、特工、技能、地图和准星标签按 VALORANT 英文术语审核；六张地图的 142 个地点标签按地图及坐标匹配英文客户端提取数据。自定义名称与原始场景、录像内容保留不变。

翻译字典位于 `patches/locales/`。构建会检查遗漏、冲突和占位符，并生成 `dist/localization-report.json`；缺失翻译会使构建失败。来源、术语边界和验收方法见 [英文界面审核说明](docs/english-ui.md)。

## 构建与启动

Linux 需要 Node.js，皮肤素材构建还需要 `ffmpeg` 位于 `PATH`。在仓库目录运行：

```bash
node prepare-offline.mjs
node verify-offline.mjs
node server.mjs
```

构建直接使用仓库内已审查的原始媒体，无需重新下载，也不依赖 `skin-packs/local/wiki-downloads/`。Windows 重建时同样需要 `ffmpeg`，并可将以上 `node` 替换为 `.\runtime\node.exe`。已有离线包可直接启动服务。

Windows 的浏览器调度修复需通过新版 `瞄准专家-离线版.exe` 启动才会带入参数。首次使用此次更新时，先保存其他 Edge 窗口中的工作，完整退出所有 Edge 实例（包括后台进程），再双击新版启动器；仅关闭训练窗口未必退出 Edge。已有 Edge 实例可能接管新的打开请求，启动器参数不会补入其既有浏览器进程。启动器沿用原 Edge 配置和本机训练数据，直接在已运行的浏览器中输入页面地址不会增加这些启动参数。 这些参数作用于启动的整个 Edge 实例，之后共享该实例的窗口也受影响。

## 枪械皮肤与击杀反馈

在“参数设置 → 音频 → 枪械皮肤与击杀反馈”中，为 Vandal、Phantom、Sheriff、Operator 分别选择可用皮肤、主题与横幅样式，并试听开火及击杀音效。ORA by OneTap 的 Base、Watch、RENEGADE、RAJA、Ignition 五个主题均支持这四种枪械；其他皮肤按原有枪械覆盖范围提供。选择保存在浏览器本机。

当前已审查并构建 **30 段真实开火音效、79 段击杀音效与 37 种分层击杀横幅**，另保留 37 张透明合成图片用于设置预览。开火音效来自已下载的 Riot 官方枪械预览视频，覆盖普通系列 10 组与 ORA 四种枪械的五套独立主题共 20 组。它们是单发实录截取，部分混响尾音在下一发前截断；Operator 保留拉栓声。面板分别显示素材缺失、加载中、失败及就绪状态，并提供单杀、连续 1–5 杀、Successive 原始片段与横幅预览。

**第一人称枪模支持现有 9 个系列、14 个枪械组合**，包括枪身、对应弹匣、瞄具和消音器。在同一面板勾选“皮肤枪模”，选择皮肤即可生效；音效、横幅与枪模的开关分别保存。枪模、71 段原始骨骼动作、40 套原始粒子配置及其可用贴图均在本地，进入训练时预载。按键位设置中的检视键（默认 **Y**）播放检视；换弹、开火、切枪和开镜会打断检视，暂停时动作停在当前时刻。切回默认或加载失败时使用原版枪模。枪械弹道、射速、伤害和训练判定不变。

枪模使用各系列标准配色；横幅配色只控制击杀横幅，ORA 五个音效主题共用其标准枪身。枪身贴图保留原始尺寸（主要为 **2048×2048**），不再缩到 1024，并启用各向异性过滤。动作按原游戏的蒙太奇配置接入：有些皮肤本来就共用基础动作，独立手部、弹匣与枪身活动部件则使用对应原始动画。换弹动作按训练的实际装弹时间同步，不改变换弹时长。

无限子弹的训练也支持手动换弹：默认按 **R**，可在“参数设置 → 键位”中修改。弹药继续保持无限；换弹期间无法开火，完成后恢复射击。有限弹药场景仍支持提前手动换弹和打空自动换弹。

枪身现按 79 种原始材质的父级默认值和实例覆盖构建。MRS 与 AEM 重组为同一张表面贴图的遮蔽、粗糙度、金属和高光四个通道，数据贴图在线性空间读取；底色保持正常色彩转换，不再额外提亮。ORA Operator 的枪身、弹匣、瞄具及镜片恢复原始零自发光设置，修复整体发白。透明与裁切状态按来源配置，RGX 的塑料外壳使用独立透明度遮罩，灯带使用专属亮度。

保留第二套原始 UV，接入波澜等水晶材质的流动贴图、绮樱花瓣扫光、Primordium 开火热光、Ayakashi 遮罩边缘光及对应表面涂层。效果只在已有枪身三角形内着色，不添加屏幕色片、折射渲染目标、泛光或顶点位移；自发光限制在可控范围内。网页的物理表面材质仍是近似，不能完全复现 Riot 自定义的明暗梯度与专用着色器，参见 [Riot 着色器说明](https://www.riotgames.com/en/news/valorant-shaders-and-gameplay-clarity)。实际白模修正及材质画面见 [枪身前后对比](skin-packs/audit/weapon-body-material-comparison.png)，逐项检查见 [枪身材质验证](skin-packs/audit/weapon-body-material-validation.json)。

开火材质读取父材质默认值和实例覆盖，使用对应的原始轮廓、透明通道、UV 旋转/滚动、动态溶解及查色表。查色表、噪声和默认贴图不再作为火焰轮廓；RGX 的棕色矩形已修正。无法可靠转换的程序光球、网格光罩、烟雾体积和缺少顶点变形的花瓣交叉面已停用，保留可用的小花瓣等原始粒子。当前保留 69 种可用材质；40 套来源配置中有 4 套附加光效因全部材质不受支持而停用，每项原因均有记录。所有 14 套枪械仍有可用枪口粒子。复杂枪身材质和特效与 Unreal 原版仍有差异，终结技未接入。逐项来源、转换及停用记录、SHA-256 见 [枪模素材审核](skin-packs/audit/weapon-model-sources.json)。离线包运行及常规重建不需要安装 VALORANT、Blender 或导出工具。

开发验证可运行 `node scripts/review-weapon-models.mjs`，再访问本机 `/__weapon-review.html`；它使用内存中的独立皮肤配置，检查原生视图模型、换弹、检视、开火特效、动作打断、默认外观恢复和相对原版基线的 GPU 资源释放。最近一次结果见 [枪模验证记录](skin-packs/audit/weapon-model-validation.json)。验证完成后删除生成的 `dist/__weapon-*` 临时文件，再运行离线校验。

使用 `node scripts/review-weapon-models.mjs --materials` 同时保存检视特写、实际材质绑定，并冻结枪的位置只推进材质时钟，检查动画像素与背景边界。该检查不改写用户皮肤选择、成绩或录像。

`node scripts/review-weapon-effects.mjs` 另生成本机 `/__weapon-fx-review.html`，对全部枪械执行腰射/瞄准、低/高散布共 56 组五发连射，检查 4088 帧。它按固定相机和背景的像素变化检测大色块回归，检查不写入用户配置。RGX 在该测试中变化超过 48/255 的画面面积从最多 26.49% 降至 1.15%；该数据不是帧率测试或实战遮挡比例。完整前后数据见 [特效验证记录](skin-packs/audit/weapon-effects-validation.json)，画面见 [RGX 修正前后](skin-packs/audit/weapon-effects-comparison.png)。

素材异步加载并提前解码；游戏开火、击杀时只读取已解码缓存，缺失或失败的素材使用原版效果。实战击杀音和图形沿用原客户端的 1–5 循环，超过五杀从第 1 段重新开始。Successive 原始片段及 Ayakashi 第 6 杀仅用于试听。横幅使用独立的外框、圆环、徽章、连杀标记与爆头图层；每次连杀会在主体周围重新排列对应数量的标记。Ayakashi 四种配色直接取用原始透明合成图中的火焰区域，不再使用通用白色标记。击杀事件早于 HUD 时钟时会保留动画；动画结束按画布实际像素完整清屏。来源与摆放参数见 [连杀图层审核](skin-packs/audit/banner-layer-review.json) 和 [Ayakashi 火焰审核](skin-packs/audit/ayakashi-flame-review.json)。

原始音轨、逐项来源、截取时间与画面证据见 [开火审核记录](skin-packs/audit/fire-review.json)。下载、构建与浏览器实测状态分别记录在 [素材状态](skin-packs/ASSET_STATUS.md)；构建方式、来源与详细操作见 [皮肤说明](skin-packs/README.md)。

## 性能优化与验证

构建时应用版本固定的补丁：训练覆盖大厅时隐藏被遮住的大厅 DOM；启动器避免 Edge 将前台游戏误降为后台节能进程；数值限帧按 RAF 时间戳推进；枪皮桥去除重复的世界矩阵和骨架更新；局部灯光使用稳定 Top-K；跳过闲置画布和空枪口层。保留原画质、枪皮、骨骼动画和特效。

弹道与命中特效现在复用有界资源。原生工厂的 80 次命中对照中，atlas 贴图克隆由 80 降至 4，预热后的 Mesh、材质分配由各 160 降至 0；销毁后无遗留材质或贴图。这是资源分配计数，不能据此断言整体 FPS 或 1% Low 已提升。空闲池各最多 64 项，场景销毁时释放。

全高清验证使用 RTX 3060 Laptop / Ryzen 7 5800H、239.760 Hz 显示器，NO.B212F6，240 帧上限、100% 比例、阴影、完整 Champions 2023 Vandal 枪模、动画与枪口特效。下表是最终正式版本的三轮相同十秒模拟脚本；每轮同期 OS 样本核对游戏前台，活动渲染进程保持 Normal 且 EcoQoS 关闭。

| 轮次 | RAF 平均 FPS | 1% Low FPS | 间隔 p99/ms | 最大间隔/ms |
| --- | ---: | ---: | ---: | ---: |
| 1 | 195.542 | 105.319 | 8.4 | 12.6 |
| 2 | 186.672 | 65.630 | 8.4 | 69.2 |
| 3 | 183.251 | 109.384 | 8.4 | 12.7 |

仍未证明稳定 240 FPS，也未证明本轮资源池化带来一致的整段 1% Low 提升。主要剩余耗时在地图绘制，骨骼不是此脚本的主要瓶颈。全量空间分批把三角形约从 218 万降至 136 万，但 draw 约从 168 增至 291，帧率下降；选择性分批及粒子合批也未显示一致收益，因此均未启用。此前大厅可见/隐藏的独立同版本 A/B 为 96.768 → 180.115 RAF FPS。

数字来自浏览器 RAF 间隔，不能称为屏幕实际呈现帧数或手动实战成绩。1% Low 按最慢 ceil(1% × 间隔数) 个原始间隔的平均值换算，不等于 1000/p99；1920×1080 使用临时 viewport override 建立渲染负载。原始机器遥测仅留本地，已跟踪的[脱敏验证摘要](docs/performance-validation-2026-10-27.json)包含逐轮结果、OS 有效性计数、资源计数和被拒绝的候选。

正式行为测试 **312/312 通过**。离线校验结果见根目录 [verification.json](verification.json)。诊断只由 scripts/create-performance-comparison.mjs 在独立目录生成，正常构建不包含诊断入口；可用 --graphics-phases 分段计时，查询参数 __repeatCurrent=3 重复当前组。可选实验函数保留供复现，不在默认构建启用。

只运行 `tests/` 下的行为测试。Linux / Bash：

```bash
node --test tests/*.test.mjs
```

Windows / PowerShell 显式枚举测试文件：

```powershell
$behaviorTests = @(Get-ChildItem -LiteralPath .\tests -Filter '*.test.mjs' -File | ForEach-Object FullName)
& .\runtime\node.exe --test @behaviorTests
```

媒体相关测试需要按[皮肤构建依赖说明](skin-packs/README.md#build-and-run-on-linux)准备 `ffmpeg`。表面贴图打包测试及部分导入脚本支持用 `FFMPEG_PATH` 指定已安装的 `ffmpeg` 可执行文件完整路径；常规皮肤媒体构建仍要求 `ffmpeg` 位于 `PATH`。请勿在根目录直接使用不带文件范围的 `node --test`，以免自动运行 `qa-artifacts/` 内的历史诊断脚本。

测试覆盖实际客户端函数和皮肤媒体构建行为；完整校验检查本机素材和脚本。真实训练中的流畅度仍取决于地图、画面设置与设备负载。

首次提交是进一步性能优化前的离线基线，标签为 `offline-baseline-2026-10-16`。第三方客户端及素材保留其原有权利归属。
